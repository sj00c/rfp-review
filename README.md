# rfp-review

- 작성 중인 제안요청서(RFP)를 사용자가 준 검토 지침에 맞춰 점검하는 Agent Skill
- 결과: 고칠 곳에 형광펜·메모를 단 한/글(HWPX) 검토본
- AI 1차 검토. 최종 판단은 담당자

## 설치

- 필요: Python 3.10 이상 (필수 패키지 없음)
- 선택: Windows + 한/글(`.hwp` 변환·결과 열림 확인), `pip install pypdf`(PDF 읽기)
- Claude Code: `git clone https://github.com/sj00c/rfp-review ~/.claude/skills/rfp-review`
- Codex CLI: `git clone https://github.com/sj00c/rfp-review ~/.codex/skills/rfp-review`
- 업데이트: 설치 폴더에서 `git pull`

## 입력

요청: 파일을 주고 "검토해 줘"

| 구분 | 개수 | 형식 | 쓰임 |
|---|---|---|---|
| RFP | 1개 (필수) | `.hwpx` `.hwp` | 메모를 다는 대상 |
| 지침 | 0개 이상, 제한 없음 | `.xlsx` `.xlsm` `.hwpx` `.hwp` `.docx` `.txt` `.md` `.pdf` | 지적의 유일한 근거 |
| 관련 문서 | 0개 이상, 제한 없음 | 지침과 같음 | 공고문·원가계산서·과업내용서 등과 문서 간 대조 |

- 지침: 첨부한 것은 항상 사용. 라이브러리(아래)에서 RFP에 맞는 것을 더 고름. 첨부도 없고 라이브러리도 비어 있으면 지침을 요청
- `.hwp` RFP: 메모는 HWPX에만 달 수 있어 한/글이 깔린 Windows에서 자동 변환. 그 밖의 환경은 한/글에서 HWPX로 저장해 줄 것. RFP가 아닌 `.hwp`는 변환 없이 읽음
- 읽지 못하는 것: 암호·배포용 HWP, 스캔 PDF·이미지. PDF는 `pypdf` 또는 `pdfplumber`가 있을 때만 읽음
- HWPX의 그림·개체는 `[그림]` `[개체]`, 수식은 `[수식: 수식 스크립트]`(HWP도 같음)로 표시. HWP·DOCX·XLSX·PDF 속 그림은 표시 없이 빠짐. 그림·개체 속 내용은 확인필요로만 지적
- 원본 파일은 읽기만 함

## 출력

- 검토본: RFP 폴더의 `output/<RFP 이름>_검토메모.hwpx` (다른 폴더를 말하면 그곳)
- 같은 이름이 있으면 `_2`, `_3`으로 새로 저장. 덮어쓰지 않음
- 메모는 RFP 한 파일에만 달림. 다른 문서의 지적은 RFP 첫 문단의 요약 메모에 위치와 함께 실음
- 채팅 답: 중요도별 건수, 필수수정 제목, 결과 경로, 검토하지 못한 것(빠진 문서·못 읽은 파일·확인필요로 남긴 지침 항목)
- 작업 폴더 `output/.rfp-review/<RFP 이름>/`: 추출 텍스트·지적 JSON 등 중간 결과. 끝나면 지움(`extract_text.py --clean`). 실패하면 남겨 두고 이어서 할 위치를 알려 줌

### 검토본 모양

- 형광펜: 노랑은 수정 필요(필수 수정 포함), 하늘색은 확인 필요. 중요도는 메모 풍선 색으로 구분
- 빨강(필수 수정): 참가자격·배점·금액·제출 방법·계약 조건, 지침이 필수라고 한 항목
- 노랑(수정 필요): 그 밖의 오류(오타·번호·문구·첨부 번호)
- 파랑(확인 요청): 문서만으로 판단할 수 없어 작성자 확인이 필요한 곳
- 메모 내용: 제목(25자 이내로 작성), 문제(80자)·수정 또는 확인(100자)·근거(60자) 각 한 줄. 이 셋은 넘치면 `…`로 자름
- 메모 글자는 문서의 '메모' 스타일(한/글 기본 9pt). 본문 글자 크기로 쓰면 풍선이 커져 잘림
- 첫 문단에 요약 메모(회색): 중요도별 건수, 처리 방법, 위치를 못 찾은 지적, 머리말·꼬리말·각주·미주의 지적, 다른 문서의 지적. 지적 제목을 다시 나열하지 않음(길면 한/글이 풍선을 잘라 보여 줌)
- 검토본에서는 문서 스크립트를 뺌(스크립트가 있으면 한/글이 메모 단 파일을 '손상' 경고로 막는 경우가 있음)

### 지적 기준

- 근거는 지침과 제출 문서뿐. 지침에 없는 내용은 지적하지 않음
- 예외: 오타·빈칸(`OOO`, `202O년`)·금액 불일치·문서 안/문서 간 모순은 지침 없이도 지적(근거: 문서 자체 오류)
- 문제만 적음. 적합 항목은 기록하지 않음
- 계약 유형(용역/물품/공사)과 낙찰 방식(협상/적격심사)을 RFP 원문으로 정하고, 그에 맞는 지침을 고름
- 금액·기간 일치, 배점 합계, 배점 비율·한도·협상적격 기준점수 같은 계산은 스크립트가 판정(`check_numbers.py`: 일치·합계·기준). 모델이 암산하지 않음
- 인용(원문)과 근거는 추출 텍스트에 그대로 있어야 통과(`validate_review.py`)

## 컨텍스트

- 한 번에 읽는 양: 8KB(한글 약 2,700자). 각 문서를 처음부터 끝까지 한 번씩 나눠 읽음
- 읽으면서 바로 지적을 `review.json`, 숫자를 `facts.json`에 적음. 따로 메모하는 단계 없음
- 지침은 판단할 수 있는 줄만 `guide_items.md`에 그대로 옮기고, 구간을 읽을 때마다 한 줄 기록
- 대화가 압축되거나 중간에 끊겨도 작업 폴더의 파일로 이어서 함. 원본이 바뀌었으면 작업 폴더를 지우고 처음부터
- 스크립트 출력 상한: 검사 오류 40건, 지침 검색 40줄, 본문에 단 메모 목록 20건까지 보여 주고 나머지는 건수만(요약 메모로 보낸 지적은 모두)

## 지침 라이브러리

- 자주 쓰는 지침을 한 폴더에 모아 두면 AI가 RFP에 맞는 것을 골라 씀
- 폴더: `~/rfp-guides/` (다른 곳이면 환경변수 `RFP_GUIDES`)
- 넣는 법: 지침 원본을 폴더에 복사. 하위 폴더 가능
- 처음 쓸 때 추출본과 적용 대상 설명을 `.index/`에 저장. 파일이 바뀌면 다시 추출하고 설명도 다시 씀
- 고르는 기준: 적용 대상 설명과 RFP 앞부분(계약 방법·사업 유형·금액). 고른 지침은 답에 적음
- 검색: `python scripts/guides.py search 하도급 공동수급 [--id <id>]` — 모든 단어가 들어간 지침 줄(공백 무시)

## 처리 흐름

1. `.hwp` RFP를 HWPX로 변환 (`hancom.py convert`)
2. 모든 문서를 위치 표시 텍스트로 추출 (`extract_text.py`): `[문단 n]` `[문단 n 표k 행-열]` `[p.쪽]` `[시트!n행]` `[줄 n]`
3. 지침 고르기 (`guides.py sync`, `describe`)
4. 문서를 나눠 읽으며 지적 작성 (`show_lines.py`)
5. 숫자 대조 (`check_numbers.py facts.json -o numeric_findings.json`)
6. 인용·근거 검사, 오류 0건까지 (`validate_review.py`)
7. 메모 달기 (`annotate_hwpx.py`)
8. Windows + 한/글이면 열림 확인 (`hancom.py check`, 안 열리면 `resave`)

스크립트는 모두 `scripts/`에 있음. 에이전트가 따르는 규칙·절차·명령·JSON 형식은 `SKILL.md`에 있음.

## 주의

- 한/글이 없는 환경에서는 결과 파일이 한/글에서 열리는지 확인하지 못함. 한/글에서 한 번 직접 열어 볼 것
- 한/글이 외부 프로그램의 파일 열기에 보안 확인 창을 띄우면 '모두 허용'을 누를 것
