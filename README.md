# rfp-review

작성 중인 제안요청서(RFP)를 사용자가 준 검토 지침에 맞춰 점검하는 Agent Skill입니다. 고칠 곳에 형광펜과 메모를 단 한/글(HWPX) 검토본을 돌려줍니다.

AI 1차 검토이며, 최종 판단은 담당자가 합니다.

## 설치

```bash
# Claude Code
git clone https://github.com/sj00c/rfp-review ~/.claude/skills/rfp-review
# Codex CLI
git clone https://github.com/sj00c/rfp-review ~/.codex/skills/rfp-review
```

- 필요: Python 3.10 이상. 설치할 패키지는 없습니다.
- 선택: `pip install pypdf`(PDF 읽기), Windows + 한/글(`.hwp` RFP 변환, 결과 열림 확인)
- 업데이트: 설치 폴더에서 `git pull`

## 사용

RFP와 지침 파일을 주고 "검토해 줘"라고 요청합니다.

| 구분 | 개수 | 형식 | 쓰임 |
|---|---|---|---|
| RFP | 1개 (필수) | `.hwpx` `.hwp` | 메모를 다는 대상 |
| 지침 | 0개 이상 | `.xlsx` `.xlsm` `.hwpx` `.hwp` `.docx` `.txt` `.md` `.pdf` | 지적의 근거 |
| 관련 문서 | 0개 이상 | 지침과 같음 | 공고문·원가계산서·과업내용서 등과 대조 |

- **지침:** 첨부한 지침은 항상 씁니다. [지침 라이브러리](#지침-라이브러리)에서 RFP에 맞는 것을 더 고릅니다. 둘 다 없으면 지침을 요청합니다.
- **`.hwp` RFP:** 메모는 HWPX에만 달 수 있어서, 한/글이 깔린 Windows에서는 자동으로 변환합니다. 그 밖의 환경에서는 한/글에서 HWPX로 저장해 주세요. RFP가 아닌 `.hwp`는 변환 없이 바로 읽습니다.
- **읽지 못하는 파일:** 암호·배포용 HWP, 스캔 PDF, 이미지. PDF는 `pypdf`나 `pdfplumber`가 있어야 읽습니다.
- **그림·수식:** HWPX·HWP의 그림·개체는 `[그림]` `[개체]`, 수식은 `[수식: …]`으로 표시됩니다. 그 안의 내용은 확인필요로만 지적합니다.
- 원본 파일은 읽기만 하고 고치지 않습니다.

### 권장 모델

같은 지침과 RFP라도 모델에 따라 놓치는 정도가 다릅니다. 샘플 RFP 2건을 모델별로 3회씩 돌린 결과입니다(정답지는 담당자 확인 전 초안).

| 모델 | 정답 중 잡은 비율 | 필수수정 중 잡은 비율 | 건당 비용 | 건당 시간 |
|---|---|---|---|---|
| Claude Opus | 0.90 | 1.00 | 약 $2.2 | 약 5.5분 |
| Claude Sonnet | 0.74 | 0.77 | 약 $1.2 | 약 4.6분 |
| Claude Haiku | 0.60 | 0.73 | 약 $0.5 | 약 7.8분 |

Opus를 권장합니다. Haiku는 이 스킬에 맞지 않습니다.

## 결과

- **검토본:** RFP 폴더의 `output/<RFP 이름>_검토메모.hwpx`(다른 폴더를 말하면 그곳). 같은 이름이 있으면 `_2`, `_3`으로 새로 저장하고 덮어쓰지 않습니다.
- **채팅 답:** 중요도별 건수, 필수수정 제목, 결과 경로, 검토하지 못한 것(빠진 문서, 못 읽은 파일, 확인필요로 남긴 항목).
- **작업 폴더** `output/.rfp-review/<RFP 이름>/`: 추출 텍스트와 판정 JSON 같은 중간 결과입니다. 끝나면 지웁니다. 중간에 끊기면 남겨 두고 이어서 할 위치를 알려 줍니다.

### 검토본 모양

| 메모 색 | 판정 | 형광펜 | 대상 |
|---|---|---|---|
| 빨강 | 필수수정 | 노랑 | 참가자격·배점·금액·제출 방법·계약 조건, 지침이 필수라고 한 항목 |
| 노랑 | 수정필요 | 노랑 | 그 밖의 오류(오타·번호·문구·첨부 번호) |
| 파랑 | 확인필요 | 하늘색 | 문서만으로 판단할 수 없어 작성자 확인이 필요한 곳 |

- 메모 한 개: 제목, 문제, 수정(또는 확인할 것), 근거. 길면 `…`로 자릅니다.
- 첫 문단에 회색 요약 메모가 달립니다. 중요도별 건수, 처리 방법, 그리고 본문에 달지 못한 지적(위치를 못 찾은 것, 머리말·각주 등, 다른 문서의 것)이 들어갑니다.
- 메모는 RFP에만 달립니다.
- 검토본에서는 문서 스크립트를 뺍니다. 스크립트가 있으면 한/글이 메모를 단 파일을 '손상'으로 막는 경우가 있습니다.

## 검토 방식

**근거**
- 지침과 제출 문서만 근거로 씁니다. 지침에 없는 내용은 지적하지 않습니다.
- 예외로 오타, 빈칸(`OOO`, `202O년`), 금액 불일치, 문서 안팎의 모순은 지침 없이도 지적합니다(근거: 문서 자체 오류).

**두 방향으로 점검**
- **체크리스트 → RFP:** 첨부한 체크리스트는 줄마다 항목이 되고, 항목마다 판정(위반·확인필요·적합·해당없음)을 남깁니다. 판정이 빈 항목이 하나라도 있으면 메모 달기로 넘어가지 못합니다. 그래서 모델이 항목을 건너뛰지 못합니다.
- **RFP → 지침:** RFP를 처음부터 끝까지 읽으며 모순, 오타, 숫자 오류를 찾습니다. 체크리스트에 없는 오류는 이 단계에서 잡힙니다.

**모델이 틀리지 않게 하는 장치**
- 금액·기간 일치, 배점 합계, 배점 한도·비율 같은 계산은 스크립트가 합니다. 모델이 암산하지 않습니다.
- 지적의 원문 인용과 근거, 적합 판정의 인용은 추출 텍스트에 그대로 있어야 통과합니다.
- 계약 유형(용역/물품/공사)과 낙찰 방식(협상/적격심사)은 RFP 원문으로 정하고, 해당 없는 체크리스트 항목은 이유와 함께 해당없음으로 둡니다.
- 메모는 문제에만 답니다. 적합·해당없음 판정은 작업 폴더의 `items.json`에만 남습니다.

**긴 문서**
- 8KB(한글 약 2,700자)씩 나눠 읽고, 읽으면서 바로 지적과 숫자를 파일에 적습니다.
- 대화가 압축되거나 끊겨도 작업 폴더의 파일로 이어서 합니다. 원본이 바뀌었으면 처음부터 다시 합니다.

## 지침 라이브러리

자주 쓰는 지침을 한 폴더에 모아 두면 AI가 RFP에 맞는 것을 골라 씁니다.

- 폴더: `~/rfp-guides/`(다른 곳이면 환경변수 `RFP_GUIDES`). 지침 원본을 복사해 넣으면 되고, 하위 폴더도 됩니다.
- 처음 쓸 때 추출본과 적용 대상 설명을 `.index/`에 저장합니다. 파일이 바뀌면 다시 만듭니다.
- 적용 대상 설명과 RFP의 계약 방법·사업 유형·금액을 보고 고르며, 고른 지침은 답에 적습니다.
- 법령·해설서처럼 긴 지침은 항목으로 만들지 않고 검색해서 근거로 씁니다: `python scripts/guides.py search 하도급 공동수급`

## 처리 흐름

| 단계 | 스크립트 |
|---|---|
| 1. `.hwp` RFP를 HWPX로 변환 | `hancom.py convert` |
| 2. 모든 문서를 위치 표시 텍스트로 추출(`[문단 n]` `[문단 n 표k 행-열]` `[p.쪽]` `[시트!n행]` `[줄 n]`) | `extract_text.py` |
| 3. 지침 고르기 | `guides.py sync`, `describe` |
| 4. 체크리스트를 항목으로 만들기 | `items.py init` |
| 5. RFP를 나눠 읽으며 지적 작성 | `show_lines.py` |
| 6. 숫자 대조 | `check_numbers.py` |
| 7. 체크리스트 항목마다 판정 | `items.py todo`, `items.py set` |
| 8. 인용·근거·판정 검사, 오류 0건까지 | `validate_review.py --items` |
| 9. 메모 달기 | `annotate_hwpx.py` |
| 10. 한/글에서 열리는지 확인(Windows) | `hancom.py check`, 안 열리면 `resave` |

에이전트가 따르는 규칙, 명령, JSON 형식은 [`SKILL.md`](SKILL.md)에 있습니다.

## 평가

체크리스트, 모델, `SKILL.md`를 바꿀 때 같은 샘플로 다시 재서 놓치는 것이 늘지 않았는지 확인합니다.

```bash
evals/run.sh opus s1 1      # 모델, 샘플, 회차
python3 evals/score.py      # 정답 중 잡은 비율, 허위 지적, 회차 간 일관성
```

- 샘플은 `evals/data/<샘플>/`에 `제안요청서.hwpx`, 체크리스트, `answers.json`(정답지)을 넣습니다. 실제 입찰 문서라 저장소에 올리지 않습니다(`.gitignore`).
- `run.sh`는 Claude Code CLI(`claude -p`)로 실행합니다.
